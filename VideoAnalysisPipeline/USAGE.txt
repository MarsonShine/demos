Video Analysis Pipeline Usage
=============================

Overview
--------

This tool takes a source MP4 and optional SRT file, then generates:

- 01.jpg                  cover image
- 01.mp4                  muted video
- 02.mp4                  copied source video
- 03.mp3                  background-music-only audio (vocals removed)
- subtitle_spans.json     parsed SRT subtitle segments
- segments.json           final aligned segments with quality flags
- segments.csv            exported segment table
- dubbing.result.xlsx     Excel workbook (sheet 1 overview + sheet 2 segments)
- review.html             static review page for click-to-seek playback
- progress.json           per-item progress and module timings

`02.mp4` and `03.mp3` also support target-size export controls.
When a target size is configured, the pipeline derives a bitrate from media duration instead of using the default copy/fixed-bitrate behavior.


1. Prerequisites
----------------

- Windows PowerShell
- Python 3.12 available through `py`
- FFmpeg and FFprobe installed and available in PATH
- SRT file exported from your video workflow if you want subtitle-driven alignment

The repository bootstrap script creates and uses `.video_pipeline_env` automatically when needed.
Keep that folder local only and do not commit it because it is machine-specific and can be regenerated.
The local `dubbing\` corpus and generated `output\` folders are also working data only and should stay out of git.
`review.html` now supports manual millisecond timing tweaks for the selected segment, browser-local save, and JSON export of those adjustments.


2. ASR Modes
------------

2.1 Local ASR: faster-whisper

Default provider:

    faster-whisper

Recommended when:

- you want local/offline processing
- you do not want to pay per request
- you can accept occasional timing edge cases that are later caught by quality flags

Relevant config in `pipeline_config.json`:

    "asr": {
      "provider": "faster-whisper"
    }

    "faster_whisper": {
      "model_size": "base.en",
      "language": "en",
      "device": "cpu",
      "compute_type": "int8"
    }

Background-music output config:

    "video": {
      "target_size_ratio": 0.0,
      "audio_bitrate_kbps": 128
    }

    "audio": {
      "method": "demucs",
      "demucs_model": "htdemucs",
      "demucs_device": "cpu",
      "mp3_bitrate_kbps": 192,
      "target_size_ratio": 0.0,
      "cache_enabled": true,
      "cache_dir": ".video_pipeline_cache\\bgm"
    }

The pipeline still extracts a temporary full-mix analysis track for ASR and silence detection.
The persisted `03.mp3` file is now the accompaniment/BGM track.
When the same source video is reprocessed with the same audio settings, the pipeline reuses the cached BGM stem instead of rerunning Demucs.
If `video.target_size_ratio` is greater than 0, `02.mp4` is transcoded toward that source-size ratio and uses `video.audio_bitrate_kbps` as the preferred embedded AAC bitrate.
If the requested video target is too small, the pipeline automatically lowers audio bitrate first, then falls back to minimum safe audio/video bitrates instead of failing the whole run.
If `audio.target_size_ratio` is greater than 0, `03.mp3` derives its MP3 bitrate from duration and the target size.
If the requested audio target is too small, the pipeline automatically falls back to the minimum 32 kbps MP3 bitrate instead of failing.

You can also override from the command line:

    --asr-provider faster-whisper


2.2 Third-party ASR: Azure Speech

Supported commercial ASR provider:

    azure-speech

Recommended when:

- you want more stable word timings and confidence
- you want fewer boundary mistakes on short words, trailing sounds, or repeated sentence patterns

Configure in `pipeline_config.json`:

    "asr": {
      "provider": "azure-speech"
    }

    "azure_speech": {
      "subscription_key": "YOUR_AZURE_SPEECH_KEY",
      "region": "YOUR_AZURE_SPEECH_REGION",
      "language": "en-US"
    }

Or set environment variables:

    $env:AZURE_SPEECH_KEY = "your-key"
    $env:AZURE_SPEECH_REGION = "your-region"
    $env:ASR_PROVIDER = "azure-speech"

You can also override from the command line:

    --asr-provider azure-speech


2.3 Video summaries: Azure OpenAI

Configure in `pipeline_config.json`:

    "azure_openai": {
      "endpoint": "https://<resource>.openai.azure.com",
      "api_key": "YOUR_AZURE_OPENAI_KEY",
      "deployment": "gpt-5.4-mini",
      "api_version": "2024-10-21"
    }

    "overview": {
      "education_stage": "小学",
      "subject": "[167070462398963715]英语",
      "source": "[7]绘本配音"
    }

Or set environment variables:

    $env:AZURE_OPENAI_ENDPOINT = "https://<resource>.openai.azure.com"
    $env:AZURE_OPENAI_API_KEY = "your-key"
    $env:AZURE_OPENAI_DEPLOYMENT = "gpt-5.4-mini"

The pipeline calls Azure OpenAI once per video, using the full subtitle corpus to generate one concise Chinese overview.
It does not call the model per segment.
When `overview.difficulty` is empty in config, the pipeline auto-estimates subtitle difficulty on a numeric `1-5` scale using sentence length, clause density, and word complexity.


3. Single-file Workflow
-----------------------

3.1 Explicit SRT input

Always wrap Windows paths containing spaces or apostrophes in double quotes:

    py run_pipeline.py single `
      --source-mp4 "C:\video-analysis\input\job-001\02.mp4" `
      --source-srt "C:\video-analysis\input\job-001\episode 01's intro.srt" `
      --output-dir "C:\video-analysis\output\job-001_review"

Target-size export example:

    py run_pipeline.py single `
      --source-mp4 "C:\video-analysis\input\job-001\02.mp4" `
      --source-srt "C:\video-analysis\input\job-001\02.srt" `
      --output-dir "C:\video-analysis\output\job-001_review" `
  --video-target-size-ratio 0.0833 `
  --audio-target-size-ratio 0.4380

3.2 Auto-discover sidecar SRT

If the SRT lives beside the MP4 and has the same stem, you can omit `--source-srt`:

    py run_pipeline.py single `
      --source-mp4 "C:\video-analysis\input\job-001\02.mp4" `
      --output-dir "C:\video-analysis\output\job-001_review"

3.3 Segment-only mode

If you only want the segment resources and do not want to call Azure OpenAI or rebuild the workbook yet:

    py run_pipeline.py single-segments `
      --source-mp4 "C:\video-analysis\input\job-001\02.mp4" `
      --source-srt "C:\video-analysis\input\job-001\02.srt" `
      --output-dir "C:\video-analysis\output\job-001_review"

This writes the media assets, `subtitle_spans.json`, `segments.json`, `segments.csv`, `review.html`, and `progress.json`.
It skips the overview summary and `dubbing.result.xlsx`.

3.4 Overview-only rebuild

If the output folder already exists and you only want to regenerate the overview workbook without rerunning segmentation, ASR, or BGM extraction:

    py run_pipeline.py single-overview `
      --output-dir "C:\video-analysis\output\job-001_review"

This reads the existing `manifest.json` and `segments.json`, calls Azure OpenAI once for that video, and rebuilds `dubbing.result.xlsx`.


4. Batch Workflow
-----------------

Batch mode now scans `--input-root` recursively.
Every folder that should be processed must contain exactly:

- one `.mp4`
- one `.srt`

The tool mirrors the input-relative folder structure under `--output-root`.

Example input tree:

    C:\video-analysis\input
    ├─ book-01
    │  ├─ 02.mp4
    │  └─ 02.srt
    └─ unit-03
       └─ lesson-02
          ├─ clip.mp4
          └─ clip.srt

Run:

    py run_pipeline.py batch `
      --input-root "C:\video-analysis\input" `
      --output-root "C:\video-analysis\output_batch"

MOD final-output run:

    py run_pipeline.py batch `
      --input-root "C:\video-analysis\input" `
      --output-root "C:\video-analysis\output_batch" `
      --final-output mod

Target-size export run:

    py run_pipeline.py batch `
      --input-root "C:\video-analysis\input" `
      --output-root "C:\video-analysis\output_batch" `
  --video-target-size-ratio 0.1233 `
  --audio-target-size-ratio 0.7380

Output tree:

    C:\video-analysis\output_batch
    ├─ book-01
    │  ├─ 01.jpg
    │  ├─ 01.mp4
    │  ├─ 02.mp4
    │  ├─ 03.mp3
    │  ├─ progress.json
    │  ├─ review.html
    │  └─ ...
    └─ unit-03
       └─ lesson-02
          ├─ 01.jpg
          ├─ 01.mp4
          ├─ 02.mp4
          ├─ 03.mp3
          ├─ progress.json
          ├─ review.html
          └─ ...

    MOD output tree:

       C:\video-analysis\output_batch
       ├─ movie_dubbing.xlsx
       └─ dubbing
         ├─ 1
         │  ├─ 01.jpg
         │  ├─ 01.mp4
         │  ├─ 02.mp4
         │  └─ 03.mp3
         └─ 2
           ├─ 01.jpg
           ├─ 01.mp4
           ├─ 02.mp4
           └─ 03.mp3

Optional filters:

- `--source-name 02.mp4` only processes folders whose single MP4 has that filename
- `--srt-name 02.srt` only processes folders whose single SRT has that filename
- `--final-output mod` switches final packaging to MOD layout (`movie_dubbing.xlsx` + `dubbing/<sequence_no>`)
- `--video-target-size-ratio 0.1233` derives a ratio-based video bitrate budget for exported `02.mp4`
- `--audio-target-size-ratio 0.7380` derives a ratio-based MP3 bitrate budget for exported `03.mp3`
- `--resume` skips batch items already marked completed in `batch_progress.json` and continues from the first unfinished item

4.1 Batch segment-only mode

To generate only the segment resources for every discovered folder:

    py run_pipeline.py batch-segments `
      --input-root "C:\video-analysis\input" `
      --output-root "C:\video-analysis\output_batch"

This skips Azure OpenAI and the merged workbook export.

4.2 Batch overview-only rebuild

To rebuild overview workbooks from existing generated outputs without rerunning the full pipeline:

    py run_pipeline.py batch-overview `
      --output-root "C:\video-analysis\output_batch"

This refreshes each child folder's `dubbing.result.xlsx`, then rebuilds the merged workbook under the batch root.
For command compatibility with normal batch mode, `batch-overview` also accepts `--input-root`, but the overview rebuild only reads existing generated outputs from `--output-root`.

4.3 Batch resume after failure

If a batch run stops midway, rerun the same command with `--resume`:

    py run_pipeline.py batch `
      --input-root "C:\video-analysis\input" `
      --output-root "C:\video-analysis\output_batch" `
      --resume

`--resume` reads `batch_progress.json`, keeps already completed items in the final merged workbook inputs, and only reprocesses the first unfinished item and everything after it.


5. Step-Skip Configuration
--------------------------

Steps can be skipped in two ways:

A) Via CLI flag `--skip` (supported by `single`, `single-segments`, `batch`, `batch-segments`):

    py run_pipeline.py single `
      --source-mp4 "C:\video-analysis\input\job-001\02.mp4" `
      --output-dir "C:\video-analysis\output\job-001" `
      --skip cover summary workbook

    py run_pipeline.py batch `
      --input-root "C:\video-analysis\input" `
      --output-root "C:\video-analysis\output_batch" `
      --skip muted-video background-audio csv

Valid step names for `--skip`:

    source-video      copy/transcode source → 02.mp4
    cover             extract first frame   → 01.jpg
    muted-video       strip audio           → 01.mp4
    background-audio  run Demucs BGM sep.   → 03.mp3
    summary           call Azure OpenAI for summary text
    workbook          write dubbing.result.xlsx
    review-page       write review.html
    csv               write segments.csv

B) Via `pipeline_config.json` under the `steps` key:
All steps default to `true`.  Set any key to `false` to skip that step.

    "steps": {
      "export_source_video":    true,   // copy/transcode source → 02.mp4
      "export_cover":           true,   // extract first frame  → 01.jpg
      "export_muted_video":     true,   // strip audio          → 01.mp4
      "export_background_audio": true,  // run Demucs BGM sep.  → 03.mp3
      "generate_summary":       true,   // call Azure OpenAI for summary text
      "export_workbook":        true,   // write dubbing.result.xlsx
      "export_review_page":     true,   // write review.html
      "export_csv":             true    // write segments.csv
    }

CLI flags override the config file for the same run.

Notes:
- Skipping `source-video` means `02.mp4` is not written; the source file is used
  in-place for all downstream metadata reads.
- Skipping `background-audio` means `03.mp3` is not written; the temporary
  full-mix analysis audio is used instead for metadata.
- Skipping `summary` sets the description field to an empty string in the workbook.
- Skipping `workbook` returns no workbook path; batch merged workbooks are also
  omitted unless at least one item produces a workbook.


6. How Alignment Works
----------------------

- SRT provides the segment text and rough subtitle timing.
- ASR provides full-audio word timings.
- The tool performs monotonic forced alignment from each SRT segment to an ASR word window.
- If the video has spoken title content before the first SRT subtitle, the tool prepends one ASR-derived title segment automatically.
- Leading SRT boilerplate such as `AI 生成` is removed automatically before alignment.


7. Review Page
--------------

Each output folder contains:

    review.html

Open it in a browser from the output folder.

Capabilities:

- click any segment to jump and play from that time
- replay the current segment
- enable "只看异常段" to show only segments with quality flags

Typical abnormal flags:

- alignment_risk
- edge_word_low_confidence
- word_duration_outlier
- neighbor_boundary_drift
- targeted_subtitle_timing_repair


8. Important Notes
------------------

- If `dubbing.result.xlsx` is open in Excel, the tool cannot overwrite it.
- If a PowerShell command uses paths with spaces or apostrophes, always quote them.
- Normal segments remain unchanged. Only flagged risky segments may receive targeted subtitle-timing repair.
- `segments.json` keeps detailed quality flags and source metadata for later review.
- In batch mode, a folder with missing or multiple MP4/SRT files fails fast instead of guessing.
- `progress.json` and `batch_progress.json` record the current stage and per-module timings while the pipeline runs.
- Workbook sheet 1 is generated automatically from the produced assets, fixed overview metadata, and the Azure OpenAI summary.
- In `batch --final-output mod`, intermediate files are cleaned after packaging, including `batch_progress.json`, `batch_summary.json`, `manifest.json`, `progress.json`, `review.html`, `segments.csv`, `segments.json`, and `subtitle_spans.json`.
- Target-size export works from media duration and source-size ratios, so actual file size is guided rather than byte-for-byte guaranteed; if the requested target is below the minimum safe bitrate floor, the tool now clamps to the minimum viable bitrate and may emit a larger file instead of failing.
- If `overview.difficulty` is set in config, that explicit value overrides the automatic `1-5` subtitle-complexity score.


9. Recommended Production Strategy
----------------------------------

Best quality:

1. Export a clean SRT from your editing workflow
2. Use Azure Speech as the main ASR provider
3. Review `review.html`
4. Focus only on segments with quality flags

Low-cost local workflow:

1. Export a clean SRT
2. Use faster-whisper locally
3. Review only flagged segments
